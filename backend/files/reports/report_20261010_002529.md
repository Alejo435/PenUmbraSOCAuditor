# Incident Report: Suspicious Process Execution and Multi-Vector External Activity

## Executive summary
Endpoint telemetry detected Microsoft Word (`winword.exe`) launching PowerShell on `workstation-04`, indicating a likely malicious document macro payload. Concurrently, user `alex` attempted an unauthorized role change to `admin` while multiple external IP addresses conducted brute-force and web directory traversal attacks against web infrastructure. The incident has been classified as high severity with an 85% confidence level, requiring host isolation and immediate containment measures.

---

## Timeline of what happened

* **20:01:26 UTC** – External IP `198.51.100.23` triggered a high-severity alert after 5 failed login attempts against the `admin` account (with additional failed attempts against `root` and `test`).
* **20:03:44 UTC** – External IP `203.0.113.77` launched path traversal probes against `host:web-server`, attempting to access `/../../etc/passwd` and `/%2e%2e/%2e%2e/etc/passwd`.
* **20:04:01 UTC** – External IP `203.0.113.77` probed for an administrative page (`/wp-login.php`) on `host:web-server`.
* **20:04:19 UTC** – The edge firewall blocked an inbound connection attempt on port 22 (SSH) from `198.51.100.23` to `host:192.0.2.50` under rule `deny_external_ssh`.
* **20:06:33 UTC** – On `host:workstation-04`, `winword.exe` spawned `powershell.exe` with command line `powershell.exe -NoProfile` (PID 5108) under user `alex`.
* **20:07:02 UTC – 20:07:10 UTC** – `host:api-02` experienced a temporary database connection timeout to `host:appdb`, which automatically restored after 8 seconds.
* **20:08:41 UTC** – User `alex` submitted a privilege change request to become `admin` on `host:auth-service` from IP `192.0.2.10`, which was denied because approval is required (`approval_required`).
* **20:09:00 UTC** – Backup completed normally on `host:storage-01` (1,842 files).
* **20:10:22 UTC – 20:10:26 UTC** – External IP `203.0.113.88` sent three rapid HTTP POST requests to `/login` on `host:web-server`, triggering HTTP 429 rate-limit errors.
* **20:11:51 UTC** – User `alex` logged out from `192.0.2.10`.
* **20:12:00 UTC** – Heartbeat status checks confirmed `web-01`, `api-02`, and `storage-01` were healthy.

## Who/what is involved

Below are the suspicious entities identified across endpoint and network telemetry:

* **`process:workstation-04/winword.exe` and `process:workstation-04/powershell.exe`**: Microsoft Word spawned a PowerShell session (`powershell.exe -NoProfile`) on workstation-04. Office applications launching command shells is a common sign of a malicious macro payload.
* **`host:workstation-04`**: The internal endpoint running the anomalous Word-to-PowerShell execution chain where user `alex` was active.
* **`user:alex`**: An internal account active on `workstation-04` that logged in via password and MFA from `192.0.2.10`, but shortly after the PowerShell event attempted an unauthorized role escalation to `admin`.
* **`ip:198.51.100.23`**: An external address conducting password brute-force attacks (5 failed attempts against `admin`, 1 against `root`, 1 against `test`) and blocked attempts to connect to SSH (port 22).
* **`ip:203.0.113.77`**: An external address scanning for web vulnerabilities via directory traversal (`/../../etc/passwd` and URL-encoded variations) and probing for `/wp-login.php`.
* **`file:/../../etc/passwd` and `file:/%2e%2e/%2e%2e/etc/passwd`**: Sensitive system credential files targeted by `203.0.113.77` during web directory traversal attempts.
* **`file:/wp-login.php`**: WordPress administrative login path targeted during reconnaissance scanning by `203.0.113.77`.
* **`ip:203.0.113.88`**: An external address generating rate-limit violations (HTTP 429) across repeated login attempts, consistent with credential stuffing.

---

## Why it matters

* **Office Launching PowerShell**: Word processors normally have no legitimate need to run scripting environments like PowerShell. When this happens, it usually means an employee opened an infected document containing malicious macros designed to download further malware.
* **Unauthorized Privilege Escalation**: User `alex` attempted to gain top-tier administrator permissions right around the time the suspicious process ran. If an attacker gains admin rights, they can disable security software, access sensitive company data, and control systems unrestricted.
* **External Attacks on Infrastructure**: While the endpoint anomaly occurred, three distinct external IP addresses probed external-facing web and server infrastructure with password guessing, SSH connection attempts, and path traversal scanning to locate sensitive system files.

---

## Recommended actions (prioritized)

1. **Isolate workstation-04**: Disconnect the host from the network immediately to prevent potential lateral movement or malware staging.
2. **Inspect PowerShell logs and parent Word document**: Examine PowerShell execution history and the originating Word document on `workstation-04` to identify any downloaded scripts or payloads.
3. **Block external IP addresses**: Add `198.51.100.23`, `203.0.113.77`, and `203.0.113.88` to the edge firewall blocklist.
4. **Interview user alex**: Review authentication session logs and interview `alex` to determine if the privilege escalation request was intentional human activity or executed programmatically through malware compromise.

---

## How our assessment changed over time

* **Initial Assessment**: At the first review of 2 events, the severity was rated **Low** with **15% confidence**. No detection rules had triggered, a read timeout occurred during analysis, and the recommendation was only to keep monitoring.
* **Final Assessment**: As telemetry expanded to 31 events, the severity escalated to **High** with **85% confidence**. Analysis confirmed high-risk process execution (`winword.exe` spawning `powershell.exe`), an attempted unauthorized role escalation by user `alex`, and concurrent external brute-force and traversal scanning.
