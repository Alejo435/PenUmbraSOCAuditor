# Incident Report: Suspicious Process Execution, Privilege Escalation Attempt, and External Probing

## Executive summary
Endpoint telemetry recorded Microsoft Word (`winword.exe`) spawning PowerShell on `workstation-04`, indicating the execution of a potentially malicious document payload. Around the same time, user `alex` initiated an unauthorized privilege escalation attempt toward an admin role, which was denied by the authentication service. Concurrently, external IP addresses conducted password brute forcing, web directory traversal, and rate limit abuse against organizational web infrastructure.

## Who/what is involved
- **`process:workstation-04/powershell.exe` & `process:workstation-04/winword.exe`**: Microsoft Word spawned PowerShell with the command line `powershell.exe -NoProfile` on `workstation-04`. Word spawning a command-line shell is anomalous behavior typical of macro execution.
- **`user:alex`**: User active on `workstation-04` when the PowerShell process spawned. Soon after, this account attempted an unauthorized role change to `admin` on `host:auth-service` from `192.0.2.10`, which was denied.
- **`ip:198.51.100.23`**: External IP address that conducted failed login attempts against `admin` (5 times), `root` (1 time), and `test` (1 time), and was subsequently blocked attempting to access port 22 (SSH) on `192.0.2.50`.
- **`ip:203.0.113.77`**: External IP address that sent HTTP requests attempting path traversal (`/../../etc/passwd` and `/%2e%2e/%2e%2e/etc/passwd`) and reconnaissance (`/wp-login.php`) against `host:web-server`.
- **`ip:203.0.113.88`**: External IP address that triggered login rate limiting (HTTP 429) three times in rapid succession against `/login` on `host:web-server`.
- **`file:/../../etc/passwd` & `file:/%2e%2e/%2e%2e/etc/passwd`**: Sensitive system files targeted during the external directory traversal attempts.
- **`file:/wp-login.php`**: Known administrative login path targeted during reconnaissance scans.
- **`host:workstation-04`**: Endpoint where the suspicious parent-child process relationship (`winword.exe` spawning `powershell.exe`) occurred.

---

## Why it matters
- **Office Application Spawning PowerShell:** Word processing software does not typically launch scripting engines like PowerShell during normal use. Attackers frequently use weaponized documents with embedded macros to execute PowerShell, allowing them to download secondary malware, stage payloads, or establish remote control.
- **Unauthorized Privilege Escalation:** An account attempting to elevate itself to administrator privileges without authorization can indicate an attacker seeking elevated control over internal systems, or an insider exceeding authorized duties.
- **Path Traversal Attacks:** Requesting paths like `/../../etc/passwd` is an attempt to navigate outside the intended public web folder to read internal operating system files. If successful, sensitive configuration details or account data could be exposed.
- **Brute Force & Rate Limit Abuse:** Repeated failed logins and rate limit violations against administrative accounts or login portals represent attempts to guess valid passwords or test compromised credentials (credential stuffing).

---

## Recommended actions (prioritized)
1. **Isolate workstation-04:** Disconnect `workstation-04` from the network immediately to prevent potential lateral movement or malware staging.
2. **Inspect PowerShell and Parent Document:** Review PowerShell execution logs and inspect the Word document opened on `workstation-04` to identify any downloaded payloads, script commands, or external network connections.
3. **Block External Attacker IPs:** Block external IP addresses `198.51.100.23`, `203.0.113.77`, and `203.0.113.88` at the perimeter edge firewall.
4. **Interview and Investigate User Alex:** Interview user `alex` and inspect active session logs to determine whether the privilege escalation request was intentionally submitted by the user or triggered programmatically via endpoint compromise.

- **Initial Assessment (Rules, 2 Events Processed):** The incident was initially classified as **Low** severity with **15% confidence**. No detection rules had matched, and the recommendation was simply to continue monitoring.
- **Final Assessment (Gemini, 31 Events Processed):** The assessment was upgraded to **High** severity with **85% confidence**. ## Confidence and gaps
- **Confidence Level:** 85% (High severity). The evidence confirms abnormal endpoint process behavior, an explicit denial of an administrative role change, and distinct web/SSH scanning patterns.
- **Gaps & Open Questions:**
  - What specific script commands or network connections did `powershell.exe` execute on `workstation-04`?
  - Did user `alex` voluntarily request admin privileges, or was the request triggered programmatically by an active compromise?
  - Were any files successfully accessed on `host:web-server` during the path traversal attempts (web server responses showed status codes 400 and 404, but full file-level access confirmation remains an open question)?
